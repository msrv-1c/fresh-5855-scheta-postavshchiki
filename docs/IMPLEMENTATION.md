# Реализация

Расширение заимствует отчет `АнализНеоплаченныхСчетовПоставщиков` и его макет `ОсновнаяСхемаКомпоновкиДанных`.

В СКД добавлены поля:

- `СуммаДокумента`;
- `СуммаОплаты`;
- `НеоплаченныйОстаток`.

Запрос отчета дополнен расчетом оплат по проведенным документам `СписаниеСРасчетногоСчета` и `РасходныйКассовыйОрдер`. Сумма берется из `РасшифровкаПлатежа.СуммаПлатежа`, если в строке заполнен `СчетНаОплату`. Если расшифровка счет не указывает, оплата связывается через `ДокументОснование` самого платежа или через платежное поручение, на основании которого он введен. Платёжное поручение без списания или расходного ордера в сумму оплаты не входит.

Также добавлен обработчик менеджера отчета:

```bsl
&НаСервере
&После("ПередКомпоновкойМакета")
Процедура ГСК5855_ПередКомпоновкойМакета(ПараметрыОтчета, Схема, КомпоновщикНастроек)
```

Обработчик вызывает `ГСК5855_ОбщегоНазначения.ВключитьКолонкиОплатыВНастройках`, чтобы новые поля гарантированно попадали в выбор отчета.

## Логика

1. СКД формирует поля:
   - `СуммаДокумента`;
   - `СуммаОплаты`;
   - `НеоплаченныйОстаток`.
2. `СуммаОплаты` считается по проведенным `СписаниеСРасчетногоСчета` и `РасходныйКассовыйОрдер`. Сначала берутся строки `РасшифровкаПлатежа` со счетом поставщика. Для платежей без такой строки сумма документа относится на счет из `ДокументОснование` либо из основания платежного поручения. Один платежный документ не суммируется дважды. Поручение без фактической оплаты не учитывается.
3. `НеоплаченныйОстаток` считается как `СуммаДокумента - СуммаОплаты`.
4. Общий модуль проверяет наличие полей в `Настройки.Выбор.ДоступныеПоляВыбора` и добавляет отсутствующие выбранные поля.

Доработка не требует привилегированного режима, COM, файловой системы или внешних HTTP-вызовов.
